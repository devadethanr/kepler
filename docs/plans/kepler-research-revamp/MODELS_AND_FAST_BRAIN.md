## Two different model families

**Preferred candidate pair, contingent on local acceptance:** Google Gemma 4 E4B QAT Q4_0 as the fast text extraction and triage service on the RTX 3060, and Qwen3.5-9B Q5_K_M as the research and critique service on the RTX 5070 Ti. This honors the preference for different model families; it does not make their answers independent evidence or guarantee quality, memory fit or speed. Compare both with the existing baseline on Kepler tasks. Use source evidence and validators, not a model vote, to determine what is accepted.

- Fast official artifact: [`google/gemma-4-E4B-it-qat-q4_0-gguf`](https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf), revision `4b4a2c1d584be7264f87aac328a1bc739ce81b6c`, file `gemma-4-E4B_q4_0-it.gguf`, 5,154,941,280 bytes, SHA-256 `676c35070db6dbe52f93e9c864ee0fba4eddea94b9c875d9cb10daff453fbaee`. Apache 2.0 per its card. The E4B has about 8B total parameters including embeddings and 4.5B effective, not a 4B total model. The file size is not GPU allocation. For text-only use, do not load the multimodal projector.
- Slow artifact: use the existing pinned `slow-qwen35` entry in [MODEL_CANDIDATES.json](MODEL_CANDIDATES.json), a community `unsloth/Qwen3.5-9B-GGUF` Q5_K_M quantization of official Qwen3.5-9B, roughly 6.58 GB file size; check the recorded revision, exact filename and SHA-256 at download. Its identity and license should be checked from the pinned repository at implementation time.
- If Gemma fails fit, latency or task-quality gates, compare the existing pinned `fast-qwen35` Qwen3.5-4B Q4_K_M (~2.74 GB file) and the currently working baseline. The fallback loses family diversity; it should be explicitly visible and is not automatic authorization to use an untested model. If neither fits, keep the known working service and report degradation. An alternative is a reduced bounded context after measuring it, not silent CPU offload or tensor splitting.

The [official Gemma card](https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf/blob/main/README.md) documents a 128K maximum for E4B, configurable thinking and native function calling; its Transformers example uses `enable_thinking=False` and supports enabling thinking. These are model capabilities, not proof that the chosen GGUF server correctly implements its chat template, thought parsing, JSON grammar or tool calls. Start triage with thinking disabled and a small output/context budget; verify the actual runtime's template and control flag. Enforce strict typed schemas through the serving runtime where supported **and** validate at the application boundary; test malformed, truncated, unknown-enum and tool-call output, failure and abstention. Never infer correctness from schema validity. No arbitrary tool access for the fast model.

The user reports both GPUs in one PC: RTX 5070 Ti 16,303 MiB and RTX 3060 12,288 MiB, driver 610.43.02 and toolkit CUDA 13.3. Current free VRAM and workload still need refreshing locally. Inventory both by UUID and free VRAM locally, including display processes, then bind one service per GPU by UUID. Measure both services resident under representative simultaneous mixed load: model weights, KV cache, context and batch sizes, CUDA/runtime overhead, fragmentation, other processes, p50/p95 queue and end-to-end latency, throughput, headroom, failures and restart/OOM stability. Record runtime/driver/GPU and artifact hashes; predefine budgets and compare extraction, factual grounding, abstention and dangerous false positives on held-out tasks. Do not infer a fit from model filename or advertised context size. Neither a download nor a benchmark was performed here.

## Decision model and fast brain

[LiquidAI/d1-2B](https://huggingface.co/LiquidAI/d1-2B) is a real, separately licensed decision-model candidate built on LFM3-VL-2B. Its card describes a single forward pass producing typed answers and probabilities without token generation. The native example calls `model.system_one(state, questions)` with `noul` yes/no, named `choice` and ordinal `score` questions. It is post-trained for decisions and is explicitly not a chat model; it does not automatically learn this operator's preferences, trading objectives or calibration. The card says calibrate thresholds on one's own data. Its H100/MI325X vendor latency is not an RTX 3060 measurement and does not prove Kepler performance or profitability. Transformers example requires custom remote model code (`trust_remote_code=True`), so pin and inspect code, dependencies and license before any trial. Its license is LFM Open License v1.0, not Apache 2.0. The [official GGUF card](https://huggingface.co/LiquidAI/d1-2B-GGUF) requires llama.cpp b11960/v0.8.0 or newer and currently supports `noul`, single `choice` and `score`; multiple choice, extraction, estimates and boxes are not yet supported there. An OpenAI chat completion client is not evidence of support for this decision interface. Its custom API/runtime, memory and license make it an offline challenger, not a third required service or a drop-in replacement for Gemma.

Build the fast brain first as an **intelligent bounded policy** on versioned, validated features: data freshness and provenance, position/portfolio state, volatility and liquidity indicators, news/event flags and confidence, existing risk and operator controls. Deterministically compute a priority, reason codes and permitted action from explicit thresholds; use hysteresis, deduplication, cooldown and per-symbol/time budgets to avoid alert storms. Allowed research actions include ignore/defer, notify, queue fast extraction, or escalate to slow research. Reject unknown, stale, conflicting, missing or out-of-range data into an explicit degraded/abstain state and preserve protective behavior. Log inputs, policy/version, timestamp, reason, decision and eventual outcome for replay. Asynchronous Gemma can annotate unstructured evidence; schema validation and provenance checks precede any use, and stale/late output is discarded. It cannot set risk limits, approve entries, place orders or modify protection.

Optional intelligence can include a compact supervised classifier or d1-2B to rank or classify *research/alerts* using labelled outcomes and operator preferences, calibrated with chronological train/calibration/untouched test splits, drift monitoring, cost-sensitive thresholds and abstention. A probability is not trustworthy solely because the model calls it calibrated; quantify calibration and false negatives/positives on representative local data. Start in offline replay, then shadow mode with deterministic fallback; promote only a versioned, independently evaluated model and policy with rollback. Training/fine-tuning is a later explicitly scoped project, not presumed available. No model is needed to operate the broker loop: no synchronous inference, waiting, or execution lock held for model/browser calls, and no model-derived automatic live approval. An urgent broker incident follows existing deterministic handling first.

## Concrete routing changes to carry forward

The current baseline at `8fb50888c47a8b4f62e0917dd0475ee5dfaa6fb0` has more than one client path. The [configuration audit](PRE_IMPLEMENTATION_AUDIT.md) finds `SmartRouter(role=...)` stores its role but does not use it for selection, while `LLMRouter.complete` does select role-specific provider/model/temperature/token settings, with separate ADK root and research settings. Do not describe all current routing as role-blind or assume changing a single cognition endpoint covers every caller. Define canonical fast/slow/baseline profiles with independent endpoint, model revision, GPU UUID, template/thinking mode, context/output/timeout/concurrency and allowed roles; map both routers and ADK call sites explicitly, including the `learning` versus `analyst` mismatch. Preserve explicit local-disabled/provider fallback behavior and prevent unexpected paid calls. Emit actual model, revision and role, queue/latency and degraded reason. Contract-test routing, malformed answers, timeout, local-disabled and all-models-down using mocks before local inference tests. Keep broker protection independent during these failures.
