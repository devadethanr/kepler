# Research Desk checks after reboot

Checks on 2026-11-01 used the normal dashboard and its same-origin research API on `http://localhost:8502` and `http://192.168.1.33:8502`, the host's current LAN address. Playwright drove a separate headless Chrome context; no existing browser profile was used. Evidence and private scripts are under `~/.local/state/kepler-rooms/prompt-tuning-20261101T205220/reboot-browser/`.

- Both origins loaded Research Desk and its lazy module only after selecting the tab. The live saved-room list, room details, and event history passed the dashboard's runtime schemas; a saved discussion displayed 28 event cards.
- Saved history could be reopened after page reload. The selected room itself resets on reload. Opening an older room by ID worked when an interception deliberately removed that room from the recent-list response; the room and history requests themselves went to the actual API.
- The LAN origin is an insecure HTTP context where `crypto.randomUUID` is absent. The actual dashboard module generated a valid UUID v4 using `crypto.getRandomValues`. Loopback also generated a valid UUID.
- A simulated network outage, created by aborting only `/api/research/**` requests in the browser, showed `Saved rooms unavailable: TypeError: Failed to fetch` and `Local model health unavailable`; the desk remained usable. A separate simulated malformed list response showed a validation error and did not crash the desk. These are simulations, not observed service outages.
- The sole console 404 was `/favicon.ico`. Initial dashboard requests aborted during the switch to Research Desk; no research API HTTP errors were recorded in the successful checks.
- With the native research worker paused, a room created and cancelled via the dashboard reached `cancelled` with `queued_cancel`, no model or tool calls, and exactly three ordered events: created, cancel requested, finished. Limits were 24 model calls, 24 tool calls and 1,200 seconds. Fetching after the final cursor returned zero events, and reopening the room by ID after reload worked. Sanitized evidence: `reboot-browser/live-queued-2026-11-01T16-41-40-598Z.json` in the private directory above.

The prepared `live.cjs` driver requires an explicit case and creation flag. `cancel.cjs` opens a specified room in the dashboard and requires an explicit cancellation flag. Their eventual results must be assessed from actual tool and message events: a model's support assessment is a proposal, not proof that its interpretation is true. The worker interruption check is recorded below.

On a subsequent **real** restart of the active `kepler-research-api.service`, polling through the dashboard proxy observed HTTP 503 for both research health and room list during the interruption, followed by three successful 200 polls. The saved cancelled room and event history response bodies were byte-identical before and after restart, including status, sequence and event IDs. Chrome reopened the room before and after reload as `cancelled · Saved discussion` and made no terminal-room SSE requests during the observation. The research worker remained paused, and only the API service was restarted. Private evidence: `reboot-browser/api-restart.json` in the directory above.

These checks used the normal dashboard, managed worker and the original runtime prompt. They do not establish a gain from any candidate prompt. Room IDs, counts, limits and sanitized event metadata are recorded privately in the files named below; no raw web HTML is included in the summaries.

- **Kepler runbook:** Both participants retrieved approved files: three successful `artifact_search` and six successful `artifact_read` results. Six public messages included two skeptic disagreements addressed to the analyst. Although the question requested graph evidence, neither participant called a graph tool; that portion of this check failed. The room ended `abstention` / `call_or_resource_limit` after 16 model and 15 tool calls. Private evidence: `live-graph-2026-11-01T16-52-02-012Z.json`.
- **SEBI browser research:** Both participants successfully called `skills_discover`, `skills_load` and `browser_read`, and there were two successful `browser_read_more` results. They exchanged nine addressed messages. The room ended `conclusion` / `outcome`, with 17 model and 17 tool calls. Tool success records retrieval; it does not verify the truth of the participants' interpretations. Private evidence: `live-browser-2026-11-01T16-52-54-472Z.json`.
- **Cancellation during browser read:** A separate room recorded `browser_read` started at 16:54:02.499 UTC, a cancel request at 16:54:02.562 UTC, then one `room.finished` at 16:54:06.959 UTC. No result for that call committed before the terminal event. This shows cancellation while the browser read was pending in the public event stream; it does not identify the internal process phase at cancellation. The room ended `cancelled` with six model and five tool calls. Private evidence: `live-browser-cancel-2026-11-01T16-53-57-176Z.json`.
- **RELIANCE graph:** A separate stock-scoped question produced two actual `graph_lookup` results, each with status `ok` and one evidence item, followed by seven addressed messages including a skeptic disagreement. Each room's terminal history reopened after a dashboard reload and returned no events after its final cursor. Counts and terminal states are observations, not a forced conclusion.

## Worker interruption and linked retry

An owned worker was killed after two model calls were admitted. After its lease expired, a replacement worker marked the room `interrupted` / `lease_expired`, retained two unresolved model activities and counted two calls with unknown usage. The recovered history had one terminal event and showed no replay of the original activity. A linked new attempt had the correct `parent_room` and fresh zero counts; it was cancelled while queued, with no model or tool calls. Two private harness assertions initially used the wrong public field shapes; they were corrected against a GET of the same attempt without additional inference. This was a test harness correction, not a product defect.

Actual Chrome checks opened both rooms by ID before and after page reload. The interrupted room displayed unknown activity and two unknown-usage calls; the retry displayed cancellation and zero unknown-usage calls. Room and history responses were unchanged across reload, and neither terminal view made an SSE request during observation. No room or model call was created by the UI check. Sanitized evidence is in [native/rooms-summary.json](evidence/prompt-iteration-v1/native/rooms-summary.json), [events-metadata.json](evidence/prompt-iteration-v1/native/events-metadata.json), and [api-restart.json](evidence/prompt-iteration-v1/native/api-restart.json). The seven native rooms together admitted 55 model calls and 50 tool calls, with three unknown-usage calls. These are admitted-call counts, not inferred completed usage.
