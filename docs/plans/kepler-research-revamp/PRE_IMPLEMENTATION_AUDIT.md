## Immediate blocker: destructive graph tests

Do not run `make test-memgraph`, a broad `make test`, or direct repository tests until graph isolation is fixed and verified. `app-test` sets `MEMGRAPH_URI=bolt://memgraph-test:7687` (`docker-compose.dev.yml:101-126`), but `config.yaml:372-377` supplies explicit graph values, so the environment-backed Pydantic default factories (`config.py:578-585`) are not invoked for those fields. `load_config` validates the YAML directly (`config.py:633-645`). The default repository reads the resulting graph configuration (`context_graph/repository/facade.py:33-47,60-70`). The fixture runs `MATCH (n) DETACH DELETE n` before/after the session and before each graph test (`tests/test_context_graph/conftest.py:18-49`). Therefore it can wipe the main graph if its configured host is reachable and authentication/schema operations succeed. Reachability and authorization were not checked. The wipe uses a default driver session, not the repository's explicitly named database (`facade.py:73-76`), which matters in multi-database deployments. `Makefile:9-25,44-52` starts test services but provides no effective graph-target guard; the marker declaration (`pyproject.toml:74-80`) alone does not exclude marked tests.

Before any destructive test, implement a fail-closed check of the actual connected endpoint and database against an explicit disposable test target, isolate the test network/service, and prove refusal for production-like targets. Check the fixture's session database as well as the repository configuration. Do not assume environment precedence alone makes deletion safe.
