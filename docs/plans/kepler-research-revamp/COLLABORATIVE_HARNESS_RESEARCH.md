## Room behavior and interface

A run starts with a pinned, as-of evidence bundle, explicit question, source permissions and a shared remaining budget. The chair requests initial independent analysis from at least two relevant roles (for example market/evidence and skeptic); thereafter agents can address one another, challenge a claim, request a permitted evidence lookup, suggest another specialist, revise a view, or ask the chair to synthesize. The chair selects next recipients/actions from current open questions and dissent; a participant may challenge the chair. Roles can return later and address new findings. These are substantive messages citing evidence IDs and uncertainty, not simulated animation or model-private chain of thought. The parent budget and evidence checks are deterministic and outside model authority. Start with at most three active roles and at most one fast and one slow inference concurrently; roles can take turns on the same endpoint. Concurrency is scheduling, not a claim of independent hardware or evidence.

Expose adapter operations `start_room(run_id, question, evidence_snapshot, budget)`, `send_message(run_id, sender, recipients, message_id, reply_to, claim_ids, evidence_ids, content)`, `request_evidence(run_id, query, as_of)`, `finish_room(run_id, conclusion)` and `cancel_room(run_id)`. Messages contain a bounded plain-language public rationale, cited evidence references, stance, unresolved questions and proposed next action; no hidden reasoning required. Messages/tools are subject to schema, length, freshness, citation, injection and permission checks. A validated final conclusion records recommendation/no-action/abstain, facts and citations, hypotheses, dissent, missing information, as-of time and result quality; the existing deterministic portfolio/risk checks and separate user approval remain the only route toward a live entry. No model message mutates an order, position, risk threshold, safety policy or account.

Stop immediately on cancellation, deadline, exhausted global calls/tokens/tool budget, authority violation, unrecoverable provider or persistence failure; mark partial/degraded/abstained with a reason and retain dissent. Otherwise the chair may conclude once each material issue is resolved, explicitly recorded as unresolved, or unavailable after a reasonable targeted lookup. Require at least two substantive participant contributions and a chance for objection before an ordinary conclusion; inadequate evidence or failed participation yields abstention/degraded, never manufactured consensus. Prevent loops with duplicate-message detection, max consecutive messages without new claim/evidence, and a deterministic parent ceiling. Initial local limits: full room 20 minutes / 24 model calls / 24 tools; short room 3 minutes / 6 calls / 8 tools. Set token admission against the configured context/output and track conservative reservations separately from actual usage. Reconcile the original 100k-input/16k-generated proposal with the passing adapter’s 32,768-context/512-output profile during implementation. Enforce call, deadline and resource ceilings outside model-editable harness material.

## Durable chat and recovery

Postgres is authoritative. A leased `ResearchRun` contains run/trigger/idempotency IDs, evidence versions/as-of, status, result quality, deadline, per-model/tool versions, remaining/reserved budget, cancellation and lease fencing token. Append immutable `RoomMessage` records with run/sequence/message ID, sender, recipients, reply/causal IDs, role, bounded content, claim/evidence refs, timestamps and validation outcome. Record tool requests/results and agent lifecycle as separate typed `ResearchEvent`s with stable IDs, parent IDs, attempts, budget consumption and sanitized artifact references. Persist message/event and outbox item in one transaction; relay via existing SSE with sequence cursor and replay/deduplication. Do not persist every token or assume a framework's own session store provides exactly-once execution. UI shows real participant messages, citations, outstanding objections and completed/failed tool outcomes; never fabricated discussion.

Use idempotent writes, one live fenced lease per room, heartbeat and bounded retries. Persist intent before each external call; after uncertain completion reconcile by request ID where possible, otherwise mark unknown and retry only safe read-only operations under a new attempt and remaining budget. Restart reconstructs from committed events and stable evidence, resumes only when framework state and child status are verified; otherwise explicitly close as interrupted and start a linked attempt, never pretend a full transcript was recovered. Disconnect/reconnect and cancellation must stop child work and reclaim resources; validate this against the chosen runtime. Outbox and run status must not claim completion before durable final artifact validation.

## Harness² belongs inside the research loop

Harness² proposes, probes and composes harness changes with fixed model weights [H1]. Integrate its task/evaluator concepts into the Room as a separate **research-only improvement job**: room agents can propose a versioned candidate prompt, skill or evidence-retrieval instruction in a disposable candidate directory; independent evaluator runs baseline and candidate against versioned, temporally separated cases; a composer may propose a combined candidate from successful probes. Record each proposal, probe result and composition as room messages/events and preserve rejected candidates. Agents consume the currently approved immutable research harness during real research; they can initiate and review candidate experiments, so Harness² is part of their working process rather than a disconnected lab. It does not mean agents may self-promote changes.

Integration requires a custom Kepler task/evaluator adapter and a proven local executor/protocol; released benchmarks do not establish Kepler performance. No runtime mutation of risk, trade permissions, executable app code, budget caps, network rules, account credentials or promotion gates. Candidates run with sanitized snapshots, no broker/network secrets, no production writable mounts and externally enforced limits. Upstream warns its default executor network is unrestricted and Codex sandbox disabled [H1]; never adopt those defaults. Development -> independently held-out temporal replay -> shadow/paper -> manual promotion of immutable version -> rollback pointer. Citation fabrication, authority violations or evidence leakage reject regardless of aggregate score; compare grounding, abstention, completion and cost/latency, not model self-praise or one PnL backtest. Weights do not change.

Acceptance: test non-scripted back-and-forth that changes an agent's position on cited new evidence; preserve unresolved disagreement; prove duplicate events, crash/restart, provider outage, incomplete usage, deadline, prompt injection, invalid citation and cancellation behavior. Under identical replay, do not exceed execution-loop latency and hard risk deadlines specified in the existing plan. A run with two agreeing models is not independent corroboration; compare claims to versioned sources. Measure usefulness prospectively, without promising alpha.
