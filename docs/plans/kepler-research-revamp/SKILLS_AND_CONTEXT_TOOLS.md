# Agent skills and research context tools

Design baseline: `origin/main` commit `8fb5088`, inspected with `git show` on 2026-10-31. This is a proposed implementation contract, not a claim that these capabilities are deployed. No application code, credentials, dependencies, or running services were changed in this audit.

## Selected runtime integration

Use [CODEX_IMPLEMENTATION.md](CODEX_IMPLEMENTATION.md). Codex App Server with the tested local adapter is the selected runtime for this personal workspace. Expose the existing graph/artifact/browser/forecast services as flat dynamic functions using the working gateway. The browser skill and real tool fixtures already passed; retain the pinned official skill/core instructions and executable service, then connect them to application research. Use one local workspace and server-owned run context; multi-tenant infrastructure is unnecessary.

## Outcome and boundary

Research agents need to discover existing graph entities, follow evidence, inspect approved research artifacts, and investigate public web sources during a run. Give each role an explicit, server-enforced capability set and typed tool gateway. Skills provide task guidance; neither skill prose, an LLM tool schema, nor the choice of an ADK/MCP transport is an authorization boundary. Enforce permissions at every tool invocation using authenticated run identity and a restricted service identity, including when a model invents a tool call or a skill asks for broader access. No arbitrary Cypher, SQL, shell, general filesystem, or broker writes are exposed to research agents.

| Role | Granted capabilities | Excluded |
| --- | --- | --- |
| Research / evidence analyst | Graph lookup, bounded neighbors and evidence; scoped research artifact list/read/search; public web search/fetch; isolated interactive browser research | Broker orders, approvals, policy/control mutation, graph writes, credentials, unrestricted execution |
| Learning / post-trade analyst | Same graph and artifact read tools where relevant; curated post-trade views | Operational or broker mutations; secrets |
| Other roles | Explicit minimum tools for their task, assigned by server policy | Inheriting all research tools merely by loading a skill |

Role membership, local workspace, run ID, permitted roots, allowed domains, rate/byte/time budgets and expiry are server-owned run context, not model-supplied authority. A local capability registry is enough; no separate multi-tenant grant service is required. If a role needs a decision or action, pass a structured proposal to the existing separate authorized workflow; research access itself never executes it. Treat retrieved pages, files and graph content as untrusted evidence, not instructions or authority to change permissions.

## Registry and discovery

Maintain versioned `SkillDescriptor {id, name, description, source_url, source_commit, content_sha256, entrypoint, runtime_version, roles, required_capabilities}` and a separate `ToolDescriptor {name, schema_version, input_schema, output_schema, capability, limits, implementation_version}`. Registry entries are reviewed, immutable per run, and selected by the orchestrator; a skill may only request tools already granted to the role. Load the full pinned `SKILL.md` and referenced pinned resources on selection; record their digests, runtime/tool versions, grant ID and tool call IDs in the run trace. Reject missing or mismatched resources rather than fetching mutable instructions during execution. Upgrades are reviewed and tested as a coherent skill/CLI pair; rollback pins both.

The official Vercel skill is [`skills/agent-browser/SKILL.md`](https://github.com/vercel-labs/agent-browser/blob/5868f7c05020e047c00e68e4abf9253cce864f41/skills/agent-browser/SKILL.md), observed at upstream commit `5868f7c05020e047c00e68e4abf9253cce864f41`. Its front matter has `name`, `description`, `allowed-tools: Bash(agent-browser:*)`, and `hidden: true`; it is a discovery stub that explicitly requires `agent-browser skills get core` before commands, with `--full` and specialized skills available from the matching installed CLI. Pin the actual CLI package/build and browser image by immutable version/digest as well as the stub, capture and review the matching `skills get core` content during build, and verify the captured digest at runtime. Do not assume the upstream `allowed-tools` field enforces Kepler permissions. Supply the official skill and matching executable to research sessions; merely adding the text to a prompt is insufficient.

For a Codex-based worker, install the reviewed skill at an appropriate repository `.agents/skills/agent-browser/SKILL.md` and make its references and matching binary available inside the worker. Codex scans `.agents/skills` from the working directory through the repository root, and user/admin/system locations; the documented front matter requires name and description. A non-Codex ADK worker must implement equivalent explicit skill discovery/loading itself. Bridge structured tools through an MCP server, ADK tool functions, or an agent app server adapter; all transports call the same authorization and validation layer. Do not hand a general Bash tool or unrestricted official browser CLI to a model. Provide an isolated browser service wrapping a reviewed command subset, so the upstream workflow is executable through an equivalent mediated interface; if a particular runtime requires literal CLI commands, expose only an enforcing wrapper under that CLI name in an isolated worker, and test every supported command against the same policy. The skill is usable during research, not just during build.

## Typed research gateway

Every response has `{status: ok|empty|partial|unavailable|unsupported_as_of|denied, data, provenance, freshness, truncated, next_cursor?, warnings[]}`. Distinguish a successful empty result from an unavailable backend. `provenance` carries source type, stable source ID, URL or allowed artifact path where applicable, observed/published and retrieval/ingestion times, content hash, and graph projection version/cursor when known. Evidence includes citations to stable entity/edge or artifact IDs and source records. Cap response size and redact disallowed fields before serialization. Set query deadline, row, hop, byte and run-wide call budgets server-side; cancel expensive backend work and return partial/truncated status, not silently complete data.

* `graph.lookup(kind, identifier, as_of?, limit?, cursor?)` resolves an allowlisted entity type and normalized exact identifier (ticker or stable ID); return ambiguous matches explicitly. `graph.neighbors(node_id, labels?, relationships?, direction?, limit?, cursor?, as_of?)` is allowlisted one-hop traversal; `graph.evidence(ticker, run_id?, limit?, as_of?)` returns candidate/run and linked evidence, marking association separately from proof of causation. Optionally expose bounded paths only after validating each intermediate node and relationship against role permissions. Default 25 rows, maximum 100 for neighbors/evidence; if paths are enabled maximum depth 3 and 50 paths, plus a backend timeout and fan-out limit. Enforce authorization on the seed and every returned node/edge; validate allowlists and reject unknown values, never interpolate user-provided Cypher.
* `as_of` means what was knowable at that instant, not merely filtering the latest node by `observed_at`. Current upserts overwrite properties and do not establish historical snapshots. Return `unsupported_as_of` unless a versioned source can prove both observation and ingestion/availability time and edge history; when supported filter both and identify the historical source/watermark. Do not claim time travel from a current projection.
* `research.list(root_id, relative_path?, cursor?)`, `research.read(root_id, relative_path, range?)`, and `research.search(root_id, query, glob?, cursor?)` operate only on explicitly mounted approved research artifact roots, not the repository or home by default. Resolve canonical paths under the root at open time, reject absolute paths, `..`, symlink escapes, device files and hard-link escape risks; use directory-relative safe opens and avoid TOCTOU. Deny `.env`, `.env.*`, secret/credential/key files and configured sensitive paths even inside a root. Restrict file types, results, lines, per-file and total bytes, search time and concurrency. Return path, content hash and mtime; no write capability. Declare unavailable or denied accurately, not an empty search.
* `web.search(query, limit?)`, `web.fetch(url)` and `browser.{open,snapshot,click,extract,close}` are scoped to public research under the same gateway. Pin a fresh isolated browser session per run, default read-only navigation and extraction; block form submission, downloads, uploads, authentication/session reuse and side-effecting requests unless a separately authorized purpose permits them. Validate each initial URL, redirect and resolved address against scheme/domain policy and block loopback, private/link-local and metadata addresses, DNS rebinding and unexpected ports. Apply per-domain rate/concurrency, redirect, content and time limits; preserve TLS verification and report blocks or paywalls. Record URL, title, retrieval time and content hash, with quoted evidence and attribution. Page text cannot expand permissions or trigger calls by itself.

### Projection freshness

`context_graph/projector.py` asynchronously polls Postgres `execution_events`, projects into Memgraph and persists an event cursor after processing; the initial sweep advances only at completion. Graph health connectivity is not freshness. Return projection cursor, latest authoritative event ID and relevant timestamps, lag/age if actually measurable, projection version, and health/last error; mark `unknown` if absent. The cursor covers this event projection, not necessarily every direct graph writer or source. State this coverage and never present cursor equality as proof all sources are current. Define freshness thresholds per use case and mark stale or unavailable; for consequential current operational facts use the authoritative curated view and identify its own freshness. No fabricated consistency guarantee between graph and Postgres.

## Current code and gaps at 8fb5088

* `context_graph/repository/facade.py` combines reads and writes behind `_run`; its metadata includes `source`, `source_id`, `postgres_table`, `postgres_pk`, `observed_at`, `ingested_at`, payload hash/json, confidence and projection version. The agent gateway must expose an independently enforced read-only interface and field allowlist, not the repository object or `_run`. Repository `get_graph_neighbors` caps 100; `expand_graph_paths` caps 50 and depth 3; `get_candidate_evidence_trace` caps 100. Their results can include all properties, and evidence is stock-linked, not necessarily run-specific proof. Add stable pagination, per-edge permissions, bounded work and provenance filtering. No general typed entity lookup or historical as-of guarantee is established by these methods.
* `context_graph/context_builder.py` offers stock, score, sector, regime, news, observation, failure and trade summaries, with several direct `_run` queries and exception-to-empty fallbacks; `get_sector_stocks` is unbounded and some caller limits lack server-side clamping. It formats compact prompts, not a complete auditable retrieval API. Adapt explicitly rather than exposing it wholesale.
* `memory_views/client.py` exposes curated Postgres views, graph summary, candidate/regime/similar-trade/lesson context, neighbors, paths, candidate evidence and research context packet. Toolbox is optional with Python fallback. Multiple graph failures become `[]` or an empty object, indistinguishable from no data; replace at gateway with typed availability and freshness. Existing Postgres fallback `open_positions` lacks the YAML tool's 50-row limit. `effective_policy` uses Python resolver as authority. Restrict outputs by role, particularly portfolio and operational details.
* `toolbox/tools.yaml` defines fixed SQL/Cypher toolsets and a Postgres source with `default_transaction_read_only=on`; research includes regime, candidate memory, neighbors and similar trades. Neighbor filters assume trusted application code. This does not prove a read-only Memgraph identity or authenticate per-agent permissions. Configure database-level least privilege, put the gateway in front of Toolbox, and validate caps even for direct toolset callers. Do not expose raw graph or Toolbox endpoints to agents.
* `llm/tool_executor.py` selects a research registry, validates tool names against it and caps model turns, then directly JSON-decodes and calls registered Python functions; tool-turn caps are not input, capability, isolation or per-operation cost enforcement. Add typed validation, run grants and gateway-side budgets. Skills and registry are separate from existing trading `SkillVersion` graph data.

## Scrapling adapter

Scrapling is approved for a bounded research extraction adapter. Pin and review a release and dependency lock/image, and expose a narrow `extract(url, selectors?, output_format?)` operation through the same web policy, isolation and provenance as browser fetch. Prefer its ordinary HTTP fetching and parsing for accessible public pages; use rendered pages only through an approved isolated browser path when needed. Do not expose its unrestricted MCP server, crawler, proxy rotation, stealth features, CAPTCHA or challenge bypass. Respect site access controls; report denial or challenge as a source limitation. No installation is part of this design audit.

Measure extraction against a versioned fixture corpus of representative static and rendered research pages: expected title, date, body, attribution, tables, links and empty/error pages, including Unicode and changed markup. Compare field precision/recall and citation span correctness against reviewed expected data and existing adapter; set acceptance thresholds before rollout. Test redirect/SSRF, content-size and timeout budgets, malformed HTML, retries, duplicate detection, stale pages, paywall/challenge detection, source hashes and no side effects. Canary with sampled human review, record failures and roll back on quality or access-policy regression. Do not treat extracted text as trusted instructions.

## Acceptance tests and rollout

1. With a seeded graph, find an entity, traverse allowed edges, and trace candidate evidence to source IDs, timestamps and projection watermark; prove disallowed labels/edges/properties and arbitrary Cypher cannot be requested, including via prompt injection. Test limits, high fan-out, timeout, deterministic pagination and stale/unavailable distinction.
2. Test `as_of` with late-arriving and overwritten facts; reject unsupported historical queries. Test projector stopped, lagging, partially failed and caught-up states against authoritative cursor, including direct-writer coverage caveat.
3. Test workspace list/read/search with normal research documents and traversal, symlink swap, hard link, `.env`, binary, oversized and unauthorized root cases. Confirm no credentials appear in result or logs.
4. In an isolated research run, discover the pinned official skill, load the matching core instructions and execute an allowed browse/snapshot/extract workflow through the enforcement wrapper. Verify forbidden commands, shell escape, local/private URLs, redirects, session crossover, form submission and writes are denied. Verify role with no browser grant cannot invoke it through any transport.
5. Contract-test identical authorization and structured errors via MCP and ADK/app-server adapters; audit run identity, skill/tool versions, requests and decisions without logging secret or sensitive content. Exercise graph, web and artifact backend failures separately.
6. Roll out read-only behind a flag to a small research cohort after fixture and integration tests pass. Compare evidence quality and bounded resource use, then expand. Keep last-known reviewed versions and disable individual capabilities independently.
