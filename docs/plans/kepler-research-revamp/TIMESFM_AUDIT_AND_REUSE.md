## What exists and what needs replacing

- `swingtradev3/data/timesfm_forecaster.py:22-36` lazily constructs the PyTorch `google/timesfm-2.5-200m-pytorch` checkpoint, process-global, with `max_context=512`, `max_horizon=128`, continuous quantile head enabled. It actually truncates input to the latest 512 observations (109-112); the caller requests 20 observations ahead. Those are application settings, not model-wide limits: upstream documents up to 16k context and a continuous quantile head up to 1k horizon. There is no explicit device selection or resource budget. `requirements.txt:43` installs Git HEAD, without a commit, and the checkpoint has no immutable revision: reproduce neither by name alone. Pin and record both, plus Torch and configuration.
- `agents/research/timesfm_agent.py:22-46` fetches daily candles from `KiteFetcher`, passes only `close`, and calls `forecast_price_range` in a thread. It retries the synchronous fetch on *any* async/model failure, potentially repeating inference and masking the initial error. Empty candles become an error; exceptions become a string error; fewer than 32 points become `{}` through `forecast_price_range`. Nevertheless it always emits “forecast generated” (53-59). This is a deterministic ADK wrapper, not a TimesFM LLM. `scanner.py:51-61` invokes it in each stock's sequence, while stocks can run in parallel. `scorer_agent.py:58-79` includes the entire stock data block in the LLM scoring prompt: forecast may influence a score, but no deterministic TimesFM weight or provable impact is specified. `context_graph/repository/facade.py:424-438` records non-error dicts including an empty dict as signal snapshots. Remove false-success messages and reject empty/degraded signals in scoring and storage.
- `data/kite_fetcher.py:21-27,76-89` gives any matching parquet cache precedence even in live mode, with no freshness or historical cutoff; async live uses direct Kite then MCP, while synchronous fallback supports direct Kite in paper/live. `tools/market/market_data.py:14-30` independently fetches day data and calculates indicators; TimesFM does not reuse a validated shared candle snapshot. No mock price generator is in this path, but cached parquet, externally supplied historical data, or older JSON may be stale or synthetic; provenance cannot be established from these routines. Tests use synthetic random-walk input (`tests/test_phase2_timesfm.py:18-26`) yet generally invoke the real model or existing cache, not a model mock. The committed `context/timesfm_cache.json` contains historical entries labelled `timesfm` (e.g. ABB dated 2026-04-18); this is not proof of current market data, real model execution, or performance. Test cache keys may collide with persisted data.
- Day is a requested candle interval, not calendar-day interpolation: no explicit frequency argument, sorting, exchange calendar, resampling, timezone normalization, completed-session rule, adjustment policy, point-in-time corporate-action treatment, or as-of cutoff is applied. `historical_close` drops date metadata when converted to NumPy. The final candle can be incomplete and a backtest can consume future candles. Split/dividend corrections and vendor adjustment basis are unknown; adjusted histories can themselves incorporate later actions. Use an exchange calendar, explicitly defined completed bars and horizon in trading sessions, point-in-time adjustment/versioned provenance, and the same data basis for labels and execution.
- Cache (`forecaster.py:42-68,88-90`) uses `ticker_horizon` and a four-hour TTL, checked before input validation. It ignores input values, source, interval, last bar/cutoff, adjustment basis, model/config versions and environment; even a historical request can receive a future/stale result. Future timestamps also pass the age test. Whole-file read/write raises concurrent update risks. The result `as_of` is generation time, not data cutoff. Replace with atomic, concurrency-safe cache keyed by a canonical request plus hash of validated point-in-time inputs, model/checkpoint/config versions, exchange, bar basis, and cutoff; enforce freshness and no future creation time. Evaluation should isolate/bypass production caches.
- Validation is limited to length >=32 (`92-104`); empty input accesses `iloc[-1]`, and NaNs, infinities, nonpositive/zero prices, unsorted/duplicate timestamps, gaps, impossible horizon, shape/crossing and freshness are unchecked. A zero last price can divide by zero. Validate before cache lookup and fail explicitly; do not silently fill financial gaps or manufacture a price.
- `forecaster.py:114-155` names the returned point path “mean” and infers quantile channel indices from array width. Corrected after the spike and pinned source inspection: `timesfm_2p5_torch.py` at e51928e27119cb17bebc005be2696b75e0a9e688 returns `(full_forecast[..., 5], full_forecast)`; configured quantile channels 1–9 correspond to nominal 0.1–0.9. Channel 0 in the full array is described as mean in the card, but is not the separately returned point. Preserve the API-returned point as `point_forecast` with version-specific metadata rather than mislabelling or reconstructing it. Assert shapes, finite values and explicit quantile ordering. The spike found raw crossings and a successful ordering fix, which is not calibration. Existing arbitrary direction thresholds and point/quantile-to-entry/stop/target logic, including fabricated ±5% bounds, remain unvalidated product behavior and must not influence risk.
- `api/main.py:32-51,65-67` warms FinBERT and TimesFM in a daemon only when `cfg.data.model_warmup_enabled`; `config.py:575` and `config.yaml:370` default it to false. Errors are logged but do not establish readiness. Lazy initialization lacks a lock and can race concurrent requests or warmup. Publish distinct unloaded/loading/ready/degraded state, use single-flight initialization and bounded inference concurrency; no startup GPU allocation by default.

## Proposed reusable contract

Implement a typed `ForecastTool` as a deterministic service callable by research, evaluation and chat. Request: instrument/exchange, field and currency, timestamped bars or immutable dataset reference, interval/calendar, last completed bar and decision cutoff, adjustment basis and source/version, context length, horizon in bars, requested explicit quantile levels, and model/config revision. Response: status (`ok`, `insufficient_data`, `invalid_data`, `unavailable`, `timeout`), reason, input provenance and hash, data cutoff, generation time, model/checkpoint/config/device, session-aligned future timestamps, point forecast and explicitly mapped quantile arrays, cache status and warnings. Validate numeric and temporal integrity, cutoff, market calendar, expected shape/order and bounds. On errors return typed degraded status and no forecast values, never synthetic fallback or success wording. Surface source staleness and do not pass degraded output as a signal. Bound runtime, queue and concurrency; record errors and observability without credentials.

A separate optional `ForecastAnalyst` chat agent is justified only if it adds interpretation: call the same tool, explain horizon, uncertainty, limitations and benchmark evidence, and cite the actual response. It must not invent confidence, convert intervals to stops, issue orders, or act as orchestrator. TimesFM remains a forecasting model, not a chat model. Existing user live-entry and manual approval workflows remain unchanged.

## Resource placement

Start CPU-only, explicit device setting, lazy single shared model per service and small bounded queue. Benchmark cold load, warm p50/p95 latency, throughput, peak RAM, concurrency and timeout on actual hardware before selecting limits. The candidate placement assigns Gemma E4B to the 3060 and Qwen 9B to the 5070 Ti, as exercised in the isolated spike; this is not a production deployment claim. Do not assume spare VRAM, cost, speed or device compatibility. If CPU misses a documented latency budget, benchmark an explicitly selected GPU with measured free and peak VRAM, model load, concurrent LLM interference and failure recovery; set reservation and operator-controlled limits, and fall back to typed unavailable when capacity is exhausted. No automatic GPU placement or six agents each loading a GPU model. Budget is a measured deployment decision, not an assumed fixed number.

## Leakage and evaluation gates

The application performs inference rather than training or fine-tuning; no application model-training causal leak is shown. However, without point-in-time slicing and cache isolation the current pipeline can leak future observations; the upstream checkpoint is pretrained on public datasets and its exact data availability and stock overlap for any historical period are not established here. Historical zero-shot results may be contaminated by pretraining; document model release/training-data provenance, use genuinely post-training holdouts when possible, and label uncertainty rather than asserting a clean causal backtest.

Before any score influence, run leakage-safe rolling-origin walk-forward evaluation across representative instruments, market regimes, historical corporate actions and horizons: each forecast sees only observations available by that decision cutoff, with point-in-time universe and adjustments, strict chronological splits, frozen configuration/thresholds, isolated caches and no overlap leakage from tuning. Compare against last observed price (random walk) and a predeclared simple drift baseline at identical cutoffs and horizons. Report per-horizon MAE/RMSE or scaled error, directional accuracy against class/base rates, quantile pinball loss, 80% interval empirical coverage and width (including crossing/conditional coverage), and confidence intervals with dependence-aware resampling. If translating forecasts into a separately specified strategy, test realistic next-executable prices, spreads, fees, slippage, turnover, liquidity, drawdown and net results against baselines, with an untouched final holdout. Predeclare minimum sample sizes and acceptance thresholds; test robustness by market and period, operational failure rates and CPU latency. Failure to outperform appropriate baselines or demonstrate interval calibration leaves the feature informational or disabled. A general time-series model may not predict financial markets profitably.
